# Supercluster Particle Artifact Script

Status: Draft for Danush review.

## Core Idea

The supercluster is the book.

Each project is not a planet or a separate object placed on top of the scene. Each project is a
temporary structure formed by the same particle field. As the user scrolls, particles from the
supercluster are pulled into focus, assemble into a project artifact, prove the work, then dissolve
back into the field before the camera travels to the next bright node.

## Narrative Grammar

Every chapter uses the same scroll grammar:

1. **Locate**: camera finds a bright density node inside the supercluster.
2. **Extract**: particles stream out of the field as filaments and signal traces.
3. **Assemble**: those particles form the project-specific model or artifact.
4. **Inspect**: camera moves around the artifact while beats reveal proof.
5. **Output**: artifact emits the result of the work as a visible flow.
6. **Release**: artifact breaks apart and returns to the supercluster.

The field always remains present. The artifact is made from the field, not added over it.

## Particle Behaviors

- **Condense**: dust tightens into a readable object silhouette.
- **Route**: filaments show input, processing, and output paths.
- **Carve**: negative space creates recognisable artifact shape without solid low-poly meshes.
- **Pulse**: active proof points brighten as the scroll crosses each beat.
- **Shear**: particles peel away during chapter transitions.
- **Rejoin**: all chapter particles return to the surrounding cluster.

## Required Model Families

- **Signal artifact**: MIRA, AIDEN, VANGUARD.
- **Scan artifact**: INSPECTION.

- **Systems map artifact**: FORMULA.

Each model family needs its own geometry language, but all must be built from particles,
filaments, and density fields.

## Development Requirements Before Modelling

1. Define artifact data for each chapter.
2. Define scroll beats for each artifact state.
3. Define particle morph rules for each model family.
4. Create still-frame image prompts for each chapter.
5. Generate visual references only after this script is approved.
6. Convert approved references into R3F and Remotion render specs.

## Quality Rules

- No literal planets.
- No chunky low-poly primitives near camera.
- No disconnected product-card object language.
- The artifact must prove the project claim visually.
- The supercluster must remain the source material for every artifact.
- Every transition must show particles leaving or returning to the field.

## Approval Gate

Approve or revise this script before image generation. Once approved, the next step is to create
one image-generation prompt per chapter and one stricter prompt for the MIRA reference frame.
